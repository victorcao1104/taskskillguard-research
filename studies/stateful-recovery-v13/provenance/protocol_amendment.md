# Common-protocol clarification before paid main experiments

The first source freeze and all 756 offline trials are retained. Eight paid development episodes used protocol v1. They exposed two ambiguities: the common tool text did not explicitly say repeated successful writes/deletes fail the study's once-only convention, and it did not explicitly state that candidate validation is isolated from real history. Several development responses confused simulated sends with committed current effects. Counterexamples named DUPLICATE_EFFECT without the repeated resource.

Before any paid main or adaptive episode, protocol v2 adds these same clarifications for EVERY method and includes repeated operation/resource/count in common validator feedback. It changes neither interpreter semantics, task instances, attack selection, correctness rules, constructor, method budgets nor final evaluation. The correction is justified by observed development responses; the offline heldout outcome counts had also been inspected, so this is not a pristine pre-data protocol freeze. V1 and v2 are kept separately and this timing is disclosed. No v1 development result is promoted to a main result.

The v2 development grid is the same eight episodes, with different campaign identities. This extra bounded pilot increases the all-campaign reservation bound from $19.35591 to $19.49682; the hard new-campaign limit stays $20. The main grid remains 1,152 episodes and adaptive grid 96 episodes. V1 offline traces remain authoritative; v2 offline replay must yield identical decisions and final traces, allowing only the additional diagnostic field.
