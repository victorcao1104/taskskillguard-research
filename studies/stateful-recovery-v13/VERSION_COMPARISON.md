# What changed from the preserved Skill-security study

The predecessor is `studies/skill-security-v12/`, based on the fifth-round approach and sixth-round executable evaluation. Its findings and paper are retained at the archived base. This version changes the recovery question and the benchmark; the two versions' percentages are **not** comparable estimates on the same task distribution.

| Dimension | Preserved v12 | New v13 |
|---|---|---|
| Main question | Which requested Skill actions are authorized, and can a legal catalogue route complete the task? | Can a legal continuation be constructed when no prepared replacement is provided? |
| Replacement knowledge | Task-specific trusted alternative scripts are available | Only generic primitives and a formal trusted task; prepared answers restricted to a labeled reference control |
| Task truth | Executable fixture goals | Independent relational-query evaluator on changing data, with held-out final inputs |
| Prior effects | Execution and recovery conditions in the earlier finite model | Explicit confirmed, failed-without-effect and uncertain history; report, delivery and cleanup obligations |
| Construction | Select a legal route from the catalogue | Slice/cut source dependencies, remove completed work, guard uncertain sends, bounded retry, model refinement |
| Strong control | Equal-information route selection and recovery controls | Source-free deterministic goal compiler plus matched repair, replan and ordinary refinement |
| Security metric | Permission and information-flow checks in the earlier environment | Full prefix plus continuation; prior leakage is never erased; separate actual effects and rejected proposals |
| Generalization | Earlier mechanism fixtures and execution conditions | Six held-out query structures, combinations, limited adaptive mutations, eight final inputs and 64 extra stress seeds |
| Skill representation | A restricted Python helper adapter with source locations | Exported `SKILL.md` plus executable JSON helper in a 16-operation DSL |
| Main limitation | Prepared catalogue already supplies much of the answer | Formal query may already make a source-free compiler sufficient; finite content validation can miss errors |

The helper-format change makes program construction and exact accounting manageable, but reduces direct coverage of real Skill source syntax. v13 does not claim to replace or improve the v12 source adapter. Neither study executes unrestricted real Skills.

The earlier report found that prepared legal alternatives restored the 24 attacked no-fault tasks, while two equally informed route selectors had identical completion outcomes on 1,344 paired conditions. Those results motivated removing the prepared-answer shortcut. They are not used as a numeric baseline against the new 24-case model grid.

Within v13, comparisons are aligned: all model methods use the same 24 cases, models, repeat counts, grants, checker and candidate-slot cap. The source-free compiler is additionally summarized on those exact cases. The strict results, full unknown-state reruns, and common normalized-protocol reruns remain separate and traceable. They are not selectively combined to choose each method's best result.

## Deviations and corrections retained

- The design's short phrase about equal call caps is clarified by the executable protocol: every method has three candidate slots, while the source constructor spends the first without an API call. Thus full/ablated methods can use two model requests, ordinary methods three. This is not equal realized spend; requests, simulation and costs are reported.
- An uncommitted send had an inconsistent successful physical trace entry. The entire affected main stratum was rerun; unaffected old episodes were reused and are not new observations.
- Stop/delete controls originally failed unblocked benign helpers because they deployed an empty continuation. Corrected controls pass through an unblocked helper; the original controls remain archived.
- Shared transport normalization was added after strict-protocol format failures were observed. All eight methods reran; the original strict results remain. Ambiguous duplicate/non-finite inner JSON is more strictly rejected by the new adapter.
- Additional 64-seed testing is post-hoc and conditional on accepted normalized programs. It is not another independent task benchmark.

The synthetic generator creates each clean helper using the same generic query compiler before injecting attacks. The goal evaluator is separately implemented, but generation and the strongest control share a query-to-operation compiler. Its strong ceiling therefore applies to this constructed language, not to independent arbitrary-task coverage. No clean helper is exported as a main-method replacement.
