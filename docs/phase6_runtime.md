# Phase 6 production runtime

This implementation was written from the prospective language specification and hand-checked tests without reading `truth_v6.py`, development fixtures, the held-out generator, or held-out fixtures. It has no external execution, network, credential, or filesystem adapter. Files and emissions are ordinary in-memory values. Tests mutate no baseline file.

## Public interfaces

* `parse_source(source)` extracts exactly one `tsg-workflow` JSON fence and returns an independently validated AST. Other Markdown is inert. Malformed/unsupported source raises `WorkflowError`, a `ValueError` subclass. Duplicate JSON keys, duplicate site IDs, recursive/unknown calls, unsupported fields/operators, nonfinite numbers, and invalid repeat counts are rejected. LF and CRLF fences are supported.
* `candidates(program)` returns all static effect dictionaries, including both branches, dead loops, and function bodies. It does not label necessity or infer grants.
* `edges(program)` returns sorted JSON arrays `[producer_id, consumer_id, relation]`, where relation is `data`, `control`, or `call`. Dataflow joins branches, expands bounded loops, and passes definitions through calls. No order edge is presented as causality. Graphs are conservative static representations, not execution traces.
* `execute(case, mode, fault='none', allowed_ids=None, world_index=0, quota=16)` parses only `case.source`. It never reads `case.program`, truth labels, family, split, or case ID. A malformed original source ends with `parse_error` before any route attempt. Malformed alternate routes remain failed candidates and cannot run effects.
* `run_semantics(program, world, goal, suppress=None)` is a diagnostic entry point using the same production evaluator with grants recorded but not enforced, no fault injection, and no receipt reuse. It returns `{files, emits, trace, goal, error}`. The trace contains `{id, op, resource, value, authorized}` for committed effects. Suppression removes all occurrences of a site, including argument evaluation, and provides an empty return value. Diagnostic goal success requires no error. This entry point is not used by recovery selection.

## Execution and recovery

Every actual attempt enters at most 100 steps, counting controls, calls, lets, and effects. Each attempt starts with fresh variables and occurrence counters. Files, emissions, receipt/signature records, fault consumption, charged quota, and duplicate counters persist across recovery attempts. Each separate `execute` call deep-copies its selected initial world.

All production modes enforce the exact same trusted `(operation, resource)` grants. A model's allowed-site list gates only original-source effects; it cannot add authority. Alternative routes are independent public ASTs checked against the same trusted grants. `route_bypass` reports any committed alternative-route effect, making recovery around an original-source model gate visible.

`guard_only` attempts the original once. `restart`, `checkpoint`, and `search` first attempt the original, retry the same original once, then consider at most two alternative routes, for at most four attempts total. Restart and checkpoint use catalog order. Checkpoint is the strong comparator: successful effects, including reads, are reused by receipt. Restart has the same observations but deliberately repeats same-signature effects. Guard-only also honors duplicate logical-effect receipts within its one attempt.

An explicit key names a logical effect across routes. A default key is `(site ID, occurrence)` and is also shared across routes; explicit and default key namespaces are distinct. Reusing a key with a different `(operation, resource, value)` fails with `receipt_conflict` before a second commit. Receipt reuses return the recorded result without charging another tool call. Quota is charged for new calls, including grants/model refusals, conflicts, and injected pre-commit failures. A call refused because quota is already exhausted cannot increase the count above quota. Expression errors occur before a call is instantiated and incur no tool charge.

The first authorized, non-reused write/emit/delete is fault eligible. A transient-before fault charges a call without committing. Known-after commits and records a receipt before returning an error. Ambiguous-after commits without a receipt and immediately stops every mode, even if the physical state satisfies the goal. There is no rollback, quota reset, or retry after an ambiguous outcome.

Search has the same catalog, grants, state, receipts, goals, attempt limit, and charged tool quota as checkpoint. After the required original retry, it simulates each remaining route on copies with no injected fault and at most 100 steps. It ranks predicted goal-achieving routes first, then no-error routes that do not finish the goal, then routes with predicted errors. Within each class it minimizes remaining charged calls; catalog index breaks ties. Simulations use no case IDs, fault schedule, reference AST, or reference truth. They do not alter live state or spend live tool quota. This is additional planning computation, not equal total compute: `planner_steps`, `simulated_effects`, and `routes_considered` explicitly record it. Every per-route estimate is retained in `search_estimates`.

## Result interpretation and limits

`files`, `emits`, and `trace` expose final simulated state and all attempted/reused production effects. Trace entries distinguish charged calls, committed effects, receipt reuse, refusals, and faults. `attempt_log` records route index, executed steps, per-attempt and cumulative charged calls, physical goal, and failure reason. Top-level fields include attempts, charged calls, remaining quota, receipt reuses, duplicate effects, unauthorized effects, failure reason, and ambiguous-stop status.

`goal` is the physical final-state predicate and can be true after a partial/error outcome. `authorized_goal` additionally requires a completed successful route and zero unauthorized commits. It is the completion measure; a refusal or ambiguous result cannot count as completion. Emission goals count exact matches for each specified resource/value pair. `duplicate_effects` counts repeated mutating commits under the same logical key, not all equal-valued emissions: repeated emissions under distinct keys can be intentional and are still checked by the exact-count goal.

Parser hardening additionally bounds syntax/call nesting to 64 and static site count to 10,000. Graph expansion stops with an explicit analysis error after 10,000 site visits, avoiding exponential preprocessing on nested finite controls. Those analysis bounds are reported coverage limits, not arbitrary-language support claims. They do not increase the 100-step execution limit.

Validation was test-first: 30 initial behavior tests failed before the runtime existed; planning counters, CRLF parsing, goal-on-error semantics, goal-aware route selection, and graph preprocessing bounds each had failing regressions before their implementation. The focused suite has 35 cases. Full project regression and independent development/held-out differential checks are coordinated by the parent after production freeze to preserve author isolation.
