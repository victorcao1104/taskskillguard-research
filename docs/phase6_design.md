# Phase 6 — executable synthetic workflow study

Status: prospective specification, 2026-10-16. User authorized design, implementation, experiments and private publication as one task. No real Skill analysis, transmission, execution or human annotation is performed. Baseline commit is `efd19d5e8704bdaec24fd183b81026d1d7fffccd`; every baseline tracked byte is preserved.

## Questions and claims

RQ1: Can an independently implemented finite interpreter derive authorization, intervention necessity and bounded route necessity, including epistemic unknowns, without detector or model labels? RQ2: Does a frozen parser/runtime handle held-out compositions of supported language constructs? RQ3: With equal routes, tools, receipts, grants, and budgets, does state-aware recovery improve on a strong checkpoint baseline? RQ4: How do source parsing, model judgments, restrictive policy and recovery jointly affect goal completion?

The object is a bounded JSON workflow language embedded in synthetic SKILL.md, not arbitrary Python or all real skills. Route necessity is explicitly relative to a supplied closed finite route catalog. We do not claim complete security, distributional generalization, or superiority over full SkillScope/Progent/CaMeL systems. Graphs are an ablation, not a presumed contribution.

## Shared language and interfaces (v1)

Source contains exactly one fenced `tsg-workflow` JSON object: `{"version":1,"steps":[...],"functions":{name:[steps]}}`. Other prose is inert. Expressions are JSON scalar literals or `{"var":"name"}`, `{"concat":[expr,...]}`, `{"upper":expr}`. File values and emitted values are strings; concat stringifies arguments. Unbound variables are errors. Only these constructs are allowed:

* `{"id":"opaque","kind":"let","name":"x","value":expr}`
* `{"id":"opaque","kind":"effect","op":"read|write|emit|delete","resource":expr,"value":expr,"out":"x","key":expr}`. `value`, `out`, `key` are optional. Read returns file text or empty string; other effects return empty string. Write replaces a file; delete removes if present; emit appends a resource/value pair. Default value is empty. Explicit key identifies a logical effect for receipt deduplication; default key is site ID plus repeat occurrence. Reuse with a different signature is an error. Reference truth has no fault injection and executes source normally, without receipt deduplication.
* `{"id":...,"kind":"if","eq":[expr,expr],"then":[steps],"else":[steps]}`
* `{"id":...,"kind":"repeat","count":integer 0..3,"body":[steps]}`
* `{"id":...,"kind":"call","fn":"name"}`. Calls must be acyclic. Site IDs are unique in the program, including function bodies. Maximum 100 steps executed per route. No OS calls, eval, network or host filesystem access.

Case schema: `case_id`, `family`, `split`, `source` (markdown), `program` (independent reference AST), `routes` (list of additional ASTs), `worlds` (nonempty list of `{files:{path:string},grants:[[op,resource],...]}`), `goal` (`files` exact required values, `absent` required absent paths, `emits` list `{resource,value,count}` with exact matching count), `catalog_closed` boolean. Public model input contains source, parsed candidates, routes, worlds, goal, closure; reference AST and computed truth are excluded. Every world is a possible completion of the supplied context, not a secret answer.

Truth API, independently written in `tsg.truth_v6`: `run(program, world, goal, suppress=None)` returns `{files,emits,trace,goal,error}`; trace lists `{id,op,resource,value,authorized}` for executed effects. Suppress a site removes all its effects and returns empty string. `evaluate_case(case)` returns `{case_id,labels:[{id,authorization,implementation,task,reasons}],...}`. Labels are yes/no/unknown. For each world: authorization requires all target occurrences authorized; no occurrence is unknown. Implementation necessity requires successful unmodified baseline and target occurrence; suppress and re-execute, goal failure means yes. Otherwise ineligible worlds are unknown. Task necessity considers original plus supplied routes that achieve goal with all effects authorized: some successful route avoids target `(op,resource)` identities => no; every successful route uses at least one target identity and catalog is closed => yes; no successful route, absent target or missing closure => unknown. Aggregate worlds: unanimous yes/no gives that label; all other mixtures => unknown. Reasons distinguish inactive, baseline failure, mixed worlds, open catalog, no legal route. This is effect-class necessity, not site identity across routes.

Production API, independently written in `tsg.runtime_v6`: `parse_source(source)` returns validated AST; `candidates(program)` returns static effect sites `{id,op,resource,...}` including both branches; `edges(program)` returns static data/control/call edge triples (all nodes may be included; no ORDER-as-causality). `execute(case, mode, fault='none', allowed_ids=None, world_index=0, quota=16)` returns JSON-serializable final state, trace, goal, authorized_goal, unauthorized_effects, attempts, charged_calls, duplicate_effects and failure reason. It must parse `case.source`, never read `case.program` or truth. Each route gets fresh variables but shared world state, receipts and charged budget. `allowed_ids=None` means all source candidates; a supplied list gates only original source effect sites, while alternative route effects pass the same trusted grants. The alternative catalog is equally supplied to every strategy; unknown model judgments cannot grant authority. All modes enforce trusted grants.

Modes: `guard_only` (one original attempt), `restart` (original retry then catalog in supplied order), `checkpoint` (same order with successful-effect receipts reused), `search` (receipt reuse plus generic estimate of remaining effect calls, catalog order tie break). Maximum four route attempts, same quota, same library and error/receipt observations. Restart has receipt access but intentionally restarts; checkpoint is the primary strong comparator. Search has no private fault schedule, case ID or oracle access. Cost selection cannot silently perform real effects. Known committed effects may be reused; ambiguous outcomes are not retried unless a receipt exists. Counts include failures before effects; no rollback or budget reset. Faults target the first write/emit/delete only: `none`, `transient_before` once before commit, `known_after` once after commit with receipt, `ambiguous_after` once after commit without receipt. Ambiguous outcome stops all strategies safely. Quota condition and under-grant condition are explicit independent axes in analysis, not hidden fifth conditions tied to family.

## Dataset and freezing

Development: 12 cases / 6 families; held-out: 24 cases / 12 families, two literal seeds per family. Held-out author reads only this spec, not production implementation, and saves separate files. Held-out families combine supported branch/call/repeat/data flow structures and include alternate routes, dead branches, legal emits/deletes, mixed worlds, and open catalogs. They must supply program/source equivalence and executable goals, without copying production code. Freeze production, truth and model protocol hashes before opening held-out fixtures. First evaluation remains immutable; repairs after that are separately labeled. Structural holdout means new compositions within this language, not new language operators or a random sample of real skills.

State is fresh per condition. Never count refusals as successful completions.

All contain identical source, worlds, catalog and candidate facts; graph adds parser edges, shuffled permutes targets, padding matches graph token length. Strict short schema returns three labels per candidate. API failures/protocol failures remain in denominators. Model outputs gate original candidates only when authorization=yes; necessity is measured independently and does not grant execution. For each main answer execute checkpoint/search at both none/transient_before, quota16, supplied grants, first world: 1,152 integrated conditions. Include an oracle-authorization gate upper bound and all-candidate trusted-guard reference. Trace stage errors and route bypasses; no claim that the model generates plans or that all three label axes cause execution outcomes.
