# 第二轮：补齐手册的自动化验收

用户在第一轮交付后要求推进到整个手册完成，随后明确：先完成所有自动化实验，人工标注包留待其安排；允许已选全部 180 个样本以每份最多 24,000 字符、12 个文件发送到 OpenAI，累计 API 预算仍为 20 USD。此轮不把未完成的人工标签伪装成 Ground Truth。

第一轮冻结在 `study-v1`，其结果文件保留。第二轮的新实现、配置、运行清单和结果独立存放。180 个原始样本及已有 family split 保持不变，不重新收集或修改语料。模型观察过的第一轮合成任务不能再次宣称为全新的未见测试集。

执行顺序与验收：

1. 核对 WP-01/02：保留论文逐页阅读、官方代码审计和最小实测；完整上游 benchmark 并非本手册最小适配的验收要求。保持来源和只读哈希检查。
2. WP-03/04/05：对全部 180 个样本生成三任务上下文、两模型 V0/V1 检测和 Q 提取。保存所有截断、无节点、无效提取和 unresolved。此轨道为真实语料的有界静态检测；真实准确率等待人工双标注及仲裁。
3. WP-06：启动真正 OS 容器，网络隔离、只读输入、资源限制、系统调用审计。实际生成 PDF/CSV/Git/邮件/HTTP/SQLite fixtures；真实源脚本仅在此隔离内执行。清楚区分原始脚本、适配流程、合成机制测试；失败保留 unsupported 原因。
4. WP-07/08：加入实际 jsonschema 校验、受限参数语法的 SMT、双账本、独立审批证据和单独的阶段到期探针。接入只读可信任务的 P 与无工具 Q，避免自由文本反馈流入 P。
5. WP-09：完整九配置（Full 与八项去组件消融），原始/中和/参考三路、独立期限与额度控制、显式 opaque 数据默认拒绝。生成合同进入执行，并与 oracle 合同分开计分；不得把修正合同后的成绩写成原始生成合同成绩。
6. WP-10：重复运行、实际 CPU/RAM、家族聚类区间、成对统计与 Holm 校正、至少五个可定位错误案例、重新生成报告和证据哈希并上传私有仓库。

可独立进行的沙箱、策略和人工审核/统计工具按并行工作技能分工。模型 API 只有主进程写共享预算账本。第二轮运行前固定各轨道配置和源代码哈希；开发验收失败可修复，但必须记录修订，不能根据正式测试表现修改提示。

人工部分的交付为两份盲审包、独立身份与导入检查、分歧仲裁表、三层标签及一致率/κ 的可重算工具。未收到真人结果前所有人工指标保持 pending。
