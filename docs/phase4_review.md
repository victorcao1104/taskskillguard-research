# 第四轮独立审查与处置

审查者与实现者分工独立，但都是自动化代理，不是手册要求的真人标注者。所有模型、提取和运行结果都保留有限语法、样例家族和来源范围。

## 采集前

- 独立作者冻结50个提取样例和24个有限推理样例；期望标签没有读取提取器输出生成。
- 审查指出 shell 参数/未知标志、Python 变量变更和身份失效、PurePath、定义时效果、错误 open 模式、HTML 区域及依赖闭包优先级问题，新增反例回归后修复。
- 首次评分有未知表示、环境访问遗漏和命令资源本体混淆；保留首次图，分别发布仅评分纠错和实现回归。后者不是新留出测试。
- 语义化候选/计划标识有泄漏标签含义的风险，采集前改为不含含义的ID；先前冻结草稿保留，没有发送其任务。
- 对384条请求逐项重算哈希、预算上界、候选映射和批准源码；120组raw/table/graph控制确认只依次加入节点和边。来源限定原批准的180份有界输入。
- Replay 将严格手册中和与有限干预因果诊断分栏；人工前置条件不能通过“破坏了依赖”被错误认定为任务必要。

## 结果后

- 逐条确认主网格完整，合成144/144、真实212/216、发现5/24协议有效；4个HTTP520、2个截断和17个来源不匹配全部保留。
- 独立检查发现轨道135个建议：125个行范围合法，0个完整来源匹配；五个有效响应均为空。原接口失败推动行ID修订，并在原12份全部样本、两模型24条条件中另行冻结复跑。
- 未发现足以修订合成真值的矛盾；也没有将模型理由当成正确标签。计分中对无效动作排除三个效果轴，缺失/无效输出继续计入计划分母；选择性准确率包含在unknown真值上的武断决策。
- 行ID修订复跑24份全部留档、20份有效、109条建议准确重建原文；逐项匹配原12样本与两模型，主384份响应哈希不变。独立复查发现模板赋值误称写文件、目录列举误称读内容、通用CLI误称HTTP POST等语义过度推断，故绝不把109条称为109个已确认能力。4份无效跨度继续保留。
- 所有图边准确率差的家族区间包含零，报告保持无一致增益结论。零宽区间不能证明总体等效。
- 执行表同时列目标完成、授权完成、越权和零执行；60/174包括缺失参考，59/173只含实际容器回执，避免不同分母看似矛盾。

## 发布材料审查

报告中的提取、推理、unknown、费用主快照、运行对照表，以及CSV和图已逐项对照保存结果。两处文字已收紧：不把旧unknown的一大部分归因于某机制而没有逐项因果分解；独立代理规定的合成真值不能称真人真值。

人工包最初复制了提取节点中的风险状态和敏感性字段，会污染独立标注；现仅给候选ID、来源跨度、哈希、独立源码包和空白字段，不给提取器或模型答案。报告生成原先可能覆盖已填写标注，现增加标签、笔记、状态和候选总体检查，已有人工工作时拒绝覆盖，并加入数据保留回归。

发布核验独立重算请求、原始解析、预算预留和结算、保存产物的评分、家族统计、原始语料哈希和空白标注限制。机器结果见 `results/phase4/provenance/release_verification.json`，文件哈希清单见同目录 `release_hashes.json`。这些校验不替代真人真值、供应商账单或对历史容器隔离的外部证明。

## 剩余限制

真实语料无法报告准确率或恶意率；128份零候选反映静态覆盖缺口。补充发现即使定位正确，语义仍未经人工确认。当前有限任务不能提供开放世界的必要性证明，当前工具守卫不能覆盖任意源码。人工标签延期、论文上游代码状态和未在本轮重跑的轨道见要求映射，不作为“自动化全部成功”处理。
