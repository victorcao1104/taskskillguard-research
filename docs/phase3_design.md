# TaskSkillGuard 第三轮设计与预先指定分析

日期：2026-10-15。用户已批准上一轮提出的修复顺序、重新实验及上传原私有仓库；真人标注继续 pending。基线为 study-v2 / 91d3688。本轮在独立 study-v3 分支实施，不修改旧 data/results 或旧报告；新代码尽量使用独立 v3 模块。

## 目标与解释边界

修复协议混淆、响应解析、计划缺步骤、人工依赖恢复和初始授权验证；分开测量模型原始能力与确定性任务编译器的收益。旧测试仅作已见回归，新任务家族作有限语法内的前瞻评估。真实 Skill 的语义准确率仍需双人标注，不由模型或研究者假设替代。

## 设计选择

采用明确的工作流步骤/权限操作分离、严格 Schema、诊断分类、必需效果检查和完整依赖来源。保留原始模型合同；越出可信任务上限的合同不能执行；漏授权不能静默补成 Oracle。独立 trusted_compile 对照从可信有限任务规格编译权限，并明确标注其来源，不冒充 LLM 改善。任务完成后才由独立 Oracle 评分；执行或恢复选择不得读取 expected_output、ground_truth 或研究者 policy。

P 只接收可信任务及目录；Q 可读取不可信 Skill 和动作，但无授权权。恢复只能选择经过合同验证的可信参考计划，不允许通过恢复扩权。公开常量 DONE 独立于机密输入，发送合同精确限制 body。未知分为传输/API、拒绝、截断、多输出、JSON/Schema、缺任务范围、范围冲突、资源未知、模型声明、计划不完整、工具不支持；非关键警告不自动使整个任务失效。

## 实验轨道

1. **历史归因与回归**：冻结并重新分类旧原始响应；在同一旧合同/计划上比较旧执行器与修复执行器，明确格式失败不可由执行器修好。另作新 P/Q 调用的已见回归，不能称 held-out。
2. **协议 2×2**：旧 development 中每个唯一可信任务规格，JSON/strict-schema × unified/split 目录，两模型、两次 replicate。保持其他提示语义不变。观察协议接受、语义范围、模型弃权，分别报告唯一请求与条件数。
3. **新任务**：16 个新转换家族，每家族 2 个输入、8 个预定场景；4 development、4 validation、8 held_out。家族包括 JSON 库存、INI 配置、日志、XML、ICS、Markdown 链接、URL 参数、Unicode 词频、Base64、ISO 日期、TSV 去重、有限 YAML、HTML 标题、JSON 路径、版本排序、温度换算。它们仍共享有限读/变换/写/通知语法，不能宣称开放世界泛化。P/Q 使用两模型、两次独立 replicate，冻结后按 split 执行，不依据 held-out 结果调参。
4. **机制对照**：固定合同、固定攻击计划；分别关闭范围、body、taint、lease、义务检查、恢复、初始授权验证。报告计划攻击机会与实际到达检查点，不把未触发记为守卫成功。原始模型合同、验证模型合同、可信规格编译合同分别报告。
5. **真实语料**：继续使用已批准的 180 个 completed 样本，24,000 字符/12 文件上限、凭证格式遮盖、原库只读。将缺操作/资源的 high 更名为 missing_scope；仅有明确范围的样本进入 explicit_effect 对照。增加明确 review_only 与 edge 条件，记录覆盖；原文/graph_v2 使用相同动作节点集合，避免改变分母。API 只由主进程共享预算对象调用。
6. **实际 OS**：复用受控适配器，修正工具目录描述并用新模型合同复跑，旧 240 条不变。新增 VM 转换不冒充 OS 执行；真实任意源码仍仅有 containment。已有人工作包保持空白并添加新条件接续说明。

## 统计与报告

主要终点：协议有效率；模型语义范围正确/缺失/过宽；全部计划条件的确认完成率；可判定条件完成率；固定攻击机会的越权与泄漏；关键/非关键未知、恢复、澄清负担；API latency/token/cost。家族 bootstrap，配对家族级效果，置信区间与独立家族数同行报告；小样本探索性，不进行数百项检验后挑选显著结果。协议实验与家族安全/效用各自预先指定比较族，保留校正及未校正统计。
