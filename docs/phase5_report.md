# TaskSkillGuard 第五轮：修复、独立新家族实验与比较

本轮完成了自动化范围内的修复和实验：新家族提取、180 份真实样本的离线覆盖复查、四维判断及 unknown、图边消融、重复稳定性，以及 180 次隔离容器中的合法恢复。人工标签仍为零，真实语料准确率尚不能计算。原始语料没有修改或执行，历史 20,899 个已跟踪文件逐字节保留。

**主要结论：提取扩展和有限合法恢复取得明确的配对改善；真实语料的覆盖改善很小；图边没有跨模型的稳定收益；unknown 的难点已经从“是否输出这个词”转向“什么时候必须保留未知、原因是否正确、下一步是否有用”。** 本轮新增费用保守上界约 **$0.410898**，累计 **$16.155451**，按已授权累计限额仍余 **$13.396124**。账本不是供应商发票。

## 1. 做了什么，什么可以比较

| 轨道 | 本轮完成 | 合理的比较单位 |
| --- | --- | --- |
| 新家族提取 | 48 个独立作者样例、24 家族、61 个效果；按家族分开发/验证/留出 | 同一批源代码上 v4 对 v5；分别报告首次验证/留出 |
| 真实 Skill | 沿用已授权 180 份有界采集；离线提取、遗漏普查、来源保留 | 候选数量和未支持区域变化；没有真人真值，不能当准确率 |
| 推理/图 | 18 新家族、50 候选、3 授权上下文、5 表示、2 模型：540 主条件 | 同一家族/候选/上下文的表示配对；家族是统计单位 |
| 重复测量 | 6 个预先按摘要选定的家族；24 个条件各做 3 次，共 72 条记录，其中 48 条新增 | 稳定性，不能算成新增独立任务 |
| q017 澄清 | 一个输入语义歧义，独立冻结 30 条补测条件 | 主结果、排除敏感性、澄清补测分别保存，不能替换首答 |
| 合法恢复 | 12 任务家族 × 5 条件 × 3 模式，实际执行 180 个容器 | 相同任务/故障上的原流程、仅拦截、拦截加恢复 |

必要性分为“固定当前实现的有限表达式干预必要性”和“固定能力假设下有限任务路线必要性”。授权条件只改精确资源或负载选择器，保留其他授权。一个动作可以在当前实现中必要，但没有得到授权；也可以在当前实现中必要，却存在另一条合法任务路线。两者都不能简化成一个危险/安全分数。

这不是手册严格源代码删除消融的完整证明，也不是任意程序语义证明。相较 Phase4，本轮家族、授权反事实和必要性估计对象改变了，因此旧推理准确率只作为历史背景，**不做跨轮准确率相减的因果解释**。正式历史表见 [historical_context.json](../results/phase5/analysis/historical_context.json)。

另一个设计限制是 50 个推理候选的动作有效性真值全部为 yes；这个维度只能检验正例识别，不能证明对无效动作的排除能力。unknown 真值只覆盖 9 种原因码中的 4 种；未覆盖原因不能按已通过处理。

## 2. 提取：新家族大幅改善，真实分布仍有缺口

| 同源配对测试 | v4 匹配/真值效果 | v5 匹配/真值效果 | v5 额外误报 |
| --- | ---: | ---: | ---: |
| 全部新家族 | 7/61，11.5% | 53/61，86.9% | 0 |
| 开发部分 | 4/24，16.7% | 22/24，91.7% | 0 |
| 首次验证 | 3/27，11.1% | 25/27，92.6% | 0 |
| 首次留出 | 0/10 | 6/10，60.0% | 0 |
| 旧 Phase4 回归 | 52/58 | 52/58 | 0 |

新样例上的精确率从 7/8 到 53/53；这是有限样例的观察值，不是总体 100% 精确率。17 个本来就不能解析目标的效果中，15 个正确保留 unknown，另 2 个被漏掉。漏掉不是正确弃答。我们保留全部 61 个效果作为主要召回分母，没有用“已经支持的语法”子集替代总体召回。

修复包括可证明身份的 Python 文件操作、别名及关键字角色，以及有限的 shell 下载/重定向。对动态绑定、别名失效、未知选项继续保守处理。冻结实现在读取隐藏验证/留出真值之前完成；留出失败没有被就地修到通过。

仍漏掉的 8 个效果有具体边界：带 mode 的 mkdir；带 follow_symlinks=False 的 copyfile；显式文件描述符 `1>`；动态 shell 输出路径；动态 wget URL 导致网络读取和已知输出写入一起丢失。最后一种暴露了可改善的实现问题：一个参数未知，不应必然丢掉同一命令中仍然可证明的独立效果。

真实 180 份样本却只从 **250→252 个全部候选、217→219 个选定候选**；零候选样本仍为 **128/180**。这不矛盾：真实未建模区域主要是外部 CLI、语言/代码块和语义不支持。旧提取器普查记录 3,041 个未建模调用、873 个不支持命令、841 个不支持代码围栏、486 个缩进代码区域；常见命令包括 uvx 139 次、npx 116 次、belt 68 次。此次标准文件 API 的扩展与真实语料主缺口并不重合。

所以新家族改善证明的是已扩展语义的有效性；真实总体覆盖还需要按实际频率扩展 CLI 和代码区域识别。**零候选不等于没有风险，也不等于已审计安全。** 数据：[提取配对](../results/phase5/extraction_primary/summary.json)、[真实覆盖](../results/phase5/real/summary.json)。

## 3. unknown：保留必要未知，拒绝无依据决定

本轮明确分开五种现象：

1. 提取漏掉：没有进入候选表，不能被下游 unknown 指标看见。
2. 接口或协议无效：没有可靠判断，按缺失/无效计分，不伪装成模型的 unknown。
3. 正确 unknown：缺授权范围、动态目标、参考路线未闭合、缺效果语义。
4. 可避免 unknown：真值已有充分信息，模型仍弃答。
5. 无依据决定：真值必须未知，模型却说 yes/no；降低 unknown 时尤其要防止这种退化。

主实验每个模型/表示有 150 个候选上下文，授权 unknown 真值为 54，其中 50 来自缺范围、4 来自动态绑定。任务必要性 unknown 的 6 条全部来自一个参考路线未闭合家族；实现必要性 unknown 的 6 条全部来自 q017，存在下述歧义。因此不能用总体 unknown 成绩掩盖原因覆盖不足。

| 表示与模型 | 授权正确 unknown | 授权无依据决定 | 任务必要性正确 unknown | 任务无依据决定 |
| --- | ---: | ---: | ---: | ---: |
| mini，节点表 | 51/54 | 1/54 | 3/6 | 3/6 |
| mini，正确图 | 42/54 | 2/54 | 3/6 | 3/6 |
| Luna，节点表 | 54/54 | 0/54 | 6/6 | 0/6 |
| Luna，正确图 | 52/54 | 0/54 | 4/6 | 0/6 |

表中未被正确未知或无依据决定覆盖的项目是协议无效造成的缺失，不应算成模型拒绝判断。Luna 的图条件少了两条任务正确 unknown，来自缺失，而非两个错误 yes/no。mini 对动态目标每种表示仅正确保留 1/4 个 unknown；有时把“目标还没绑定”直接当作“没有授权”。

未知原因也会错：mini 的正确图条件中，3 个任务 unknown 虽标签正确，原因码正确数却为 0/6。保存的 q016 反例中，解释文字指出路线集合不完整，结构字段却填 missing_scope。这说明字段非空、JSON 有效、unknown 标签正确，是三个不同层次的检查。现有证据/下一步字段只检查存在性，没有真人语义评分，不能宣称建议有效。

**q017 的处理是实验设计修正，而非模型失败重试。** 原输入把 UNSPECIFIED 写成普通字符串，同时声称省略响应语义未知；普通字符串真值与这句话冲突。独立审查在作者和审查者读取输出前发现问题，采集已经开始，所以保留原输入、真值和首答；附 17 家族排除敏感性，并为明确“抽象未知标记、不是运行值”的版本采集完整 30 条条件。补测全部协议有效，但实现必要性正确 unknown 仍只有每个模型/表示 **3/6 或 4/6**。这提示歧义不是全部原因；一个家族的改善也不能当总体提升。主结果、敏感性、补测必须并列阅读。[勘误](phase5_truth_erratum.md) · [补测结果](../results/phase5_q017/analysis/summary.json)

结构化授权规则基线在已提供候选和授权上达到 150/150，包括全部 54 个 unknown。它说明这些有限授权关系可以用确定规则判定；它依赖候选声明，不是从真实源码端到端提取，也不解决必要性。

## 4. 图边：改进了控制，仍没有稳定贡献

五个表示共享同一源码、任务、候选和上下文：节点表、自动图、独立正确图、打乱图，以及与正确图等输入 token 的中性填充。正确图有 42 条独立真值边；自动图投影匹配 32/42、无额外边，端到端边召回 76.2%。这个分数包括提取和映射，不等同于原始图提取器的单独召回。漏边集中在辅助函数/调用、可变别名、文件往返和循环。

所有 108 对正确图/填充在本地计数和供应商返回输入 token 上都完全相等。但这只控制了输入长度，没有控制输出长度、内容引导或注意分配。

以下全部使用计划分母，协议无效按未答对计入。每格分母为 150。

| 模型、指标 | 节点表 | 自动图 | 正确图 | 打乱图 | 等长填充 |
| --- | ---: | ---: | ---: | ---: | ---: |
| mini，实现必要性 | 120 | 114 | 116 | 118 | 113 |
| mini，任务必要性 | 124 | 113 | 117 | 121 | 114 |
| Luna，实现必要性 | 122 | 126 | 127 | 133 | 125 |
| Luna，任务必要性 | 136 | 142 | 142 | 141 | 138 |

Luna 正确图比节点表的实现必要性提高 3.33 个百分点，家族配对 95% 区间为 [-2.04,+8.64]；任务必要性提高 4.00 点，区间 [-2.22,+10.49]。mini 同方向比较为负，区间也跨 0。Luna 的实现必要性最高点估计来自打乱图，不能把点估计的提升简单归因于正确依赖关系。排除 q017 后，两模型的正确图/节点表必要性比较区间仍跨 0。

并非所有区间都跨 0：mini 自动图的任务必要性降低 11/150，即 -7.33 点，探索性区间 [-13.89,-1.39]。事后配对分解中，净损失 8 个正确答案来自只有一侧协议有效的配对；另 3 个来自两侧都有效的 126 对。这是端到端损失分解，不是剔除失败后得到无偏“纯图效应”。未做多重比较校正。[配对区间](../results/phase5/analysis/paired_comparisons.jsonl) · [协议分解](../results/phase5/publication_v2/protocol_pair_decomposition.json)

没有稳定收益有四个可区分原因：

- **图表示的能力边界。** 依赖边说明值或控制如何流动，不直接证明对目标必要。一个有依赖的分支可以被覆盖、短路或替代；一个没有入边的清理操作也可能是目标的一部分。
- **模型概念混淆。** q010 中 mini 用“任务可以直接替代”推翻固定当前实现的必要性；q014 中忽略省略值 0 仍能让循环达到目标。这是干预语义和参考路线理解问题，增加边不自动解决。
- **表示和协议成本。** 更多信息不保证完整回答。mini 主条件有效率为 table 50/54、auto 47/54、oracle 48/54；整体图分数包含这部分可用性损失。
- **有限设计的识别能力。** 每家族只有一个基础实例，图与源码信息重叠，重复还会波动。打乱图不保证每条边都假；中性填充不能完全消除内容效应。因此本实验只能说“尚未显示稳定增益”，不能说“图普遍无用”。

另一个必须披露的事实：**588 主采集条件实际对应 510 次独立请求**。主 540 条件对应 462 次，附加重复 48 次；13 家族的自动图和正确图输入完全相同，78 对条件共享缓存答案，只有 q007/q008/q009/q010/q014 五家族的两种图输入不同。它们仍是合法的管线条件比较，但自动/正确图的一致性不能当独立重复证据。q017 补测 30 条件对应 24 次独立请求。实际新请求共 534 次，与新账本预留一一计数吻合。

主 510 次独立原始回答中，503 completed、6 incomplete、1 API error，严格协议有效 484；条件加权为 555/588 有效，主条件为 509/540。错误保留，未自动挑选重试。主分析 `usage_all_jobs` 为条件加权 token，不是实际请求用量；独立主请求上报输入 721,226、输出 190,342，共 911,568 token。[请求与用量审计](../results/phase5/publication_v2/request_cache_audit.json)

重复稳定性也未支持图能稳定判断：24 个三次重复组中只有 14 组全部有效且完整标签向量一致；mini 表/正确图为 6/6、5/6，Luna 为 2/6、1/6。稳定不等于正确，mini 有稳定重复的错误。此小面板不能据此排列模型总体稳定性。

## 5. 合法恢复：同时检查目标、副作用和额度

恢复使用受信任的有限参考路线，在同一进程、同一网关、同一额度和效果记录上继续。获准尝试在 I/O 前扣额度，失败也不退回；已经写入的结果不重复写；原有越权不能被后续成功抹除。原始 Skill 不参与执行。容器无外网、无宿主目录挂载、非 root、只读根目录，镜像摘要固定。

| 模式 | 正常授权内成功 | 故障时只看目标完成 | 故障时授权内核心目标完成 |
| --- | ---: | ---: | ---: |
| 原流程（观察性对照） | 12/12 | 22/48 | 3/48 |
| 仅拦截 | 12/12 | 0/48 | 0/48 |
| 拦截并合法恢复 | 12/12 | 40/48 | 40/48 |

恢复解决了全部人工前置条件 12/12、必要工具生效前失败 12/12、部分执行后失败 12/12，以及过宽契约 2/2、输入完整性 2/2。仍未恢复的 8 个条件是额度耗尽 3、授权过窄 3、库中没有已知合法参考路线 2。它们没有靠扩权或重置额度强行成功。

全网格观察到 21 个未授权效果，全部来自原流程；两个防护模式均为 0。全部模式重复效果为 0。单独“什么也没做”的条件不构成安全有效性的充分证据，所以必须与 40 个实际授权内成功一起看。正常模式 12/12 说明本面板的正常使用未损失，不能外推真实产品零开销。

这是本轮最明确的可用性进展：只拦截会让故障任务停住；有已知、可验证、额度内的替代实现时，可以完成大部分任务。剩余 8 个不是一律需要“放宽防护”：额度/授权不足需要新增用户依据，没有注册替代路线则需要补充可审计的合法实现。没有路线不证明任务本身不可能。

边界也很明确：12 个转换任务仍共享读取输入、写结果、本地确认的外壳；第五种条件因家族而异，不能独立分离条件效应；本地确认不是远端网络服务。有限工具网关结论不能声称封锁了任意恶意 Python 或系统调用。[实际 180 次结果](../results/phase5/recovery_primary/summary.json)

## 7. 证据指向的后续工作顺序

1. **先取得来源级真人真值，再决定真实覆盖扩展优先级。** 使用现有 832 条盲标包；尤其审核零候选、CLI、未支持语言和截断，不只确认已提取节点。按命令频率与真实效果扩展 uvx/npx 等适配器，同时允许同一命令部分效果已知、部分未知。
2. **把 unknown 做成可检验的分支。** 分别补授权、动态值、路线闭包和效果契约；对每种原因构造信息补齐前后配对。扩充当前未覆盖的原因类型，加入无效能力负例。用确定规则处理结构化授权，模型负责较难的源代码映射与语义解释。
3. **先降低协议负担，再重测图的增量。** 四轴分阶段或缩短每候选输出，按预注册方案比较完整率与语义质量；保留严格失效指标。图输入只给与具体目标相关的最小路径/反事实证据；构造源码与节点表相同、关系不同且答案确实改变的干预家族。
4. **针对图差异本身采样。** 新增辅助调用、别名、循环、文件往返家族，每家族多实例；正确/错误/无边对照保证关系差异，长度精确匹配。若测随机稳定性，必须使用不同 replicate；同输入复用缓存只适合确定管线对比。先冻结主要比较和多重检验处理，再新增采集。
5. **扩展合法恢复的证据范围。** 增加不同工具结构、并发/中断/幂等键、不可回滚外部效果和明确恢复成本；使用完整家族×故障设计。在更复杂恢复仍证明不扩权、不重置额度、不重复提交后，再进入经人工审核的真实 Skill 试点。
