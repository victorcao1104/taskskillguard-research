# Phase 6 supplementary equal-planning selection

`tsg.selection_v6.execute_selection(case, mode, fault='none', allowed_ids=None, world_index=0, quota=16)` adds two supplementary modes: `first_feasible` and `search_equal`. It imports the existing frozen runtime's private VM, parser, estimator, validation, goal predicate, and result builder. No frozen runtime, original experiment result, reference interpreter, or original test is changed.

Both modes first attempt the source program and, after a recoverable failure, retry that same original once. They share files, emissions, grants, receipts, signatures, charged quota, and fault consumption across attempts. Each attempt gets fresh variables and occurrence counters, the same 100-step bound, and the same original-site model gate. Known receipts are reused. Ambiguous outcomes stop immediately. Alternative execution still requires trusted grants. The total limit is four actual route attempts.

At each alternative selection point, both modes estimate **every remaining route**, in catalog order, using the same frozen `_estimate` operation. Each estimate evaluates a copy of the current public state and receipts, uses the trusted goal and grants, and has the same 100-step bound. It receives no fault schedule, reference AST, truth labels, case ID, family, model output beyond the supplied original-site gate, or challenge fixture metadata. Simulation has no external effects and does not change live state, receipts, or charged-call quota.

Both modes use exactly the same feasibility predicate: no predicted error, predicted goal achievement, and predicted remaining calls no greater than the current remaining charged-call quota. The estimate computes the route's bounded total call requirement before the identical quota filter is applied. An invalid alternative is recorded as a non-feasible `route_parse_error` candidate with zero simulated steps. This preserves its place in the candidate denominator without executing it.

`first_feasible` selects the first feasible catalog entry. `search_equal` selects the feasible entry with the lowest estimated calls, breaking ties by catalog index. The chosen entry is removed from the remaining catalog. If no candidate is feasible, including an empty catalog, both stop with `failure_reason='no_feasible_route'`; that planning decision is not an actual attempt and incurs no additional charged call. Earlier terminal parse, ambiguous-outcome, or quota-exhaustion errors retain their original reason.

The return value contains the frozen runtime's state, traces, attempts, physical `goal`, completed `authorized_goal`, charged-call costs, receipt/duplicate/unauthorized counts, and planning counters. `search_estimates` now records an estimate for **both** modes, with additional `remaining_quota` and `feasible` fields. `planner_steps`, `simulated_effects`, and `routes_considered` retain their existing definitions.

Two additional result fields support the comparison:

* `selection_log`: one record per planning decision, containing the proposed attempt number, remaining quota, candidate count, feasible route indices in catalog order, and the selected route index (or `null`).
* `initial_feasible_catalog_count`: the number of feasible routes at the first alternative decision; `null` if execution ends before any planning decision, and zero when a decision finds none.

The strategies perform identical planning work at a shared observed state over a shared remaining catalog. Their first alternative decision therefore has identical estimates and planning counters. Their different selections can lead to different subsequent states or remaining catalogs after a fault. Whole-run planning totals are measured and must not be asserted equal when those execution histories diverge. The comparison holds planning capabilities and algorithm fixed; it does not grant either strategy hidden information or require artificial duplicate simulations to equalize divergent histories.

This is a targeted mechanism control added after the original results were preserved. It cannot establish the population prevalence of cheaper-route opportunities or universal search superiority. Catalog counterbalancing can produce ties, and lower unconditional costs must be interpreted with completion and jointly successful conditional costs.

The 22 focused tests use hand-written manual cases and were observed failing before the new implementation existed. They check equal planning records with different successful costs, reversed-catalog and equal-cost ties, quota-based feasibility, no-feasible and empty catalogs, known/ambiguous receipts, original-only model gating, grant enforcement, four-attempt fault recovery, unchanged simulation state, goal/error/conflict filtering, source fail-closed behavior, ignored private metadata, and invalid-route accounting. Challenge fixtures, their generator, and model outcomes were not read before this implementation's freeze. Parent-coordinated evaluation supplies independent fixture and full regression checks.
