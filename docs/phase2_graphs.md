# Phase 2：受限 Python 数据依赖图

`src/tsg/graph_v2.py` 在不导入、不运行真实 Skill 代码的条件下，增加简单变量赋值、路径表达式、DATA 边和显式分支节点。旧 `graph.py`、旧图和正在使用的模型输入均未修改。新输出位于 `results/phase2/graphs_v2/`。

## 实测覆盖

固定原 180 个 Skill，每个 bundle 最多 24,000 字符、12 个文件。v1 和 v2 都对同一份有界文本重新抽取，避免把输入增多当作算法改进。共分析 430 个文件；74 个文件截断，2,447 个文件省略。按 manifest 对原文件在运行前后哈希检查，变化为 0；没有网络或模型调用，没有执行 corpus 代码。

| 指标 | v1 同输入 | v2 |
|---|---:|---:|
| 候选动作 | 4,125 | 4,097 |
| 已知资源候选 | 274 | 300 |
| 所有候选的资源解析比例 | 6.64% | 7.32% |
| 代码候选 | 202 | 174 |
| 已知资源代码候选 | 10 | 36 |
| 代码候选的资源解析比例 | 4.95% | 20.69% |
| DATA 边 | 0 | 1,609 |
| 有 DATA 边的 Skill | 0 | 26 |
| 读/取数据候选至写/发送候选的 DATA 可达对 | 0 | 6 |
| 显式 PREDICATE 节点 | 0 | 728 |
| CALL / RETURN 边 | 43 / 36 | 21 / 16 |
| 未解决记录 | 59 | 3,509 |

这些是**候选与结构覆盖计数，不是语义准确率、召回率或漏洞检出率**。v2 不再把失去工具绑定的同名调用当作确定工具调用，并收紧跨文件命令引用，因此代码动作与 CALL/RETURN 数量会下降；未经人工标注，不能断言减少的全是假阳性。未解决记录增多来自逐调用、分支、函数作用域的显式记账，不是同一误差口径下的退化率。

资源覆盖改善仍然有限。实际 corpus 的 174 个代码候选中，138 个资源未知，29 个为 AST 字面量，7 个为非 Python 词法字面量，**没有**本轮实际 corpus 候选被标记为 `resolved_constant`。变量路径解析已由独立 fixture 行为测试验证，但不能声称它在这个被截断样本上带来已观测收益。文档候选占多数；4,097 个总候选仍有 3,797 个未知资源。

完整原始图为 `{skill_id}.json`，逐 Skill 对照为 `coverage.jsonl`，汇总为 `summary.json`，文件与输入 SHA-256 为 `manifest.json`。

## 支持的语义

- Python 常量赋值、变量别名、字符串加法、简单无格式化 f-string、`pathlib.Path/PurePosixPath` 的单字符串构造与 `/` 连接。
- 识别导入别名后的 requests/httpx、受限文件操作、环境变量读取与 subprocess 命令候选。`open` 与 `.read/.write` 作为不同源调用分别记录；不会把两个节点自动视为两个已执行外传。
- 为赋值生成 DATA_OBJECT，为受控调用生成 CODE_ACTION，显式参数与接收者形成 `may_value_dependency` DATA 边。未知函数只保留可能的参数依赖，不声称函数纯净、输出等价、没有副作用或完成脱敏。
- `if` 与条件表达式建立分支局部 CONTROL 边，不把 then 分支与 else 分支串成同一执行路径。所有分支常量相同才保留；不同值或只有一边赋值则合并为 unknown。
- 简单赋值和 `:=` 会覆盖旧常量；未知赋值、循环变化、属性写入、复杂解包等保守地使常量未知。循环不求固定点。
- 每个函数有独立词法作用域；不把模块变量的当前值视为未来调用时不变。模块全局重绑定不会意外恢复 builtin/import 工具身份。函数节点只代表代码候选，不证明函数被调用。
- Python 注释和包含调用文本的字符串不会变成可执行调用节点。非 Python 文件仍仅作显式标记的词法候选，常见整行注释略过。
- Markdown 中明确运行脚本的引用指向模块入口；返回边标为 `syntactic_return_candidate`，不声称脚本一定结束。部分文件名匹配（例如 `main.py.evil`）不会连接到 `main.py`。

所有节点保留来源文件和行跨度，解析得到的资源另保存常量来源链。空 Python 文件不会生成虚构的可定位动作。完整 AST 解析失败记录 `python_parse_error`；本次样本有 9 条，截断输入可能导致该现象。

## 未解决与限制

本次明确记录的主要限制：2,520 个未建模调用、297 个未证明调用/全局状态的函数、126 个未计算固定点的循环、102 个分支常量不确定、73 个未支持语句、60 个未知资源表达式。其余原因及计数均保留在 summary。

不支持完整跨过程调用、points-to/别名分析、任意类构造、动态导入、真实 shell/JS/TS 语义、异常路径完整控制流、隐式数据流或主机路径解释。`os.path.join` 标为平台语义未知；生成路径的 pathlib 子集使用 POSIX 词法表示，不能用于主机文件授权。未支持表达式/语句可能包含本提取器遗漏的行为，因此 `analysis_complete` 始终为 false。图不能直接签发权限，仍需可信任务合同、运行时检查和任务验证。
