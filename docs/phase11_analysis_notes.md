# Phase 11 analysis implementation notes

`scripts/analyze_phase11.py` implements the frozen estimands in `phase11_analysis_plan.md`. It reads saved evidence only, imports no selector, interpreter or API client, and does not reconstruct unobserved decisions. `summarize(...)` is a pure entrypoint returning `tables` and `summary`; its optional row collections support independent toy tests. The CLI verifies the data freeze and complete case, policy, recovery, stream, integrated, semantic and previous-contract grids before writing any analysis file. It requires acquisition and integrated finalization summaries. It writes JSONL and CSV tables plus summary and hash manifest to `results/phase11/analysis/`, rejecting different existing bytes.

Each reported condition first averages the stated variants/worlds/conditions within a structural family, then averages families equally. Main, challenge and their clearly labelled combined 36-family aggregate are separate. Dependent scaling siblings are never included in the combined aggregate; scaling shape remains a condition. Reported `rows`, `pairs`, `known_rows`, `missing_rows` and raw totals are measurement denominators and counters, not independent sample sizes. A condition with missing numeric values reports the missing count and the number of contributing families. Execution costs absent because no certificate was issued are missing, not zero-cost executions.

All intervals resample families with replacement 10,000 times using Python's `random.Random(11101)` in sorted family order. The same sample identities apply to equal family counts. Percentiles use linear interpolation at 2.5% and 97.5%. Optional installed NumPy accelerates arithmetic; a standard-library fallback is provided. Paired contrasts first match the same case and world at the stated budget/condition, compute row differences, then average differences within each family before resampling. Contrast direction is always left minus right, including costs where a positive difference means more work. Wins/losses/ties count matched row differences, while positive/negative/zero-family counts describe family means. Missing pairs are explicit and never silently imputed. Intervals and individual-family effects are descriptive; there are no p-values or significance labels.

The primary model comparator uses source online versus the predeclared observe-cover policy at the model's actual selected world and budget 12. Other budgets and all alternate heuristics are also reported. Graph/source and graph/padding contrasts retain view and model identity. Fresh source online/fixed differences measure independently acquired streams, including their different selector choices. Matched-prefix rows are conditional on an observed positive witness: route equality, full result equality, and both-success are distinct. Offline saved queries are counterfactual work and never invoice savings.

Every finalized API stream remains in every applicable task and reliability denominator. Task completion is actual authorized goal completion from its verified paid-prefix certificate, independent of whether a later decision invalidates the full stream. A fixed stream may already have sufficient evidence before an invalid later response; its existing certificate is retained without inventing another query. `stream_valid` and `valid_complete_stream_success` separately describe full-stream protocol reliability. Invalid streams with no sufficient paid prefix fail completion. `partial_paid_prefix_success` exposes the prefix endpoint directly. Budget rejection is separate from provider/protocol failure and affected stream/family/cells are saved in `budget_censored_streams`.

Reliability work records attempted decisions, pre-I/O budget rejections, confirmed provider response statuses, uncertain transport/interruption, completed record envelopes, schema-valid selections, parsed JSON objects, full valid streams, and paid-prefix success separately. `valid_json_objects` means the strict parser returned an object, including a possible schema-invalid object; a malformed envelope is never rescued from a convenience text field. Known token totals sum nonnegative integer usage fields only and retain missing-usage counts. Conservative cost includes reservations when usage is unknown. Elapsed sums preserve the acquisition runner's accounting and report missing latency records; they are not parallel campaign wall time.

Unknown classifications use the independent reference's full-observation class: an available common route means budget-limited certifiability; no common route means unresolved robust infeasibility. This is the robust fixed-route contract, not actual-world impossibility. Unknowns remain unknown, and unavailable observations are a separate flag. Negative certificates are known robust infeasibility. Hindsight minimum positive certificate cost is a privileged independent reference bound, never a selectable policy. The cost gap is defined only for a returned positive certificate and reports its own missing denominator.

Recovery tables retain missing certificates and untriggered faults. The primary two first-mutation terminal fault contrasts at status budget 1 report both all-row and triggered-only denominators. The same-ID dedup rows and contrasts explicitly require a stronger atomic durable backend capability. The previous-runtime table is an unequal-access contract comparison and cannot isolate a causal repair effect.

Semantic tables compare independent reference, audit and fault-free actual execution files, emits, success, calls, receipt reuse and errors; independent/audit entered steps are also compared. The raw reference and audit error strings remain in each row. As disclosed in `phase11_reference_normalization.md`, only independent `unbound_variable:<name>` is mapped to `unbound_variable`; executor `goal_unmet` maps to error-free VM termination followed by an unmet goal. Trace encodings are not asserted identical by the analysis; the independent reference validation artifacts contain the more detailed event comparison. Raw error-string differences and normalized mismatches are separately counted. Neither reference nor production evidence is rewritten.

`scripts/plot_phase11.py` checks the complete analysis manifest, then creates six restrained Matplotlib figures with PNG, SVG and PDF exports and exact CSV source values under `results/phase11/figures/`. Outcome and cost axes start at zero; paired completion differences span -100 to 100 percentage points. Scaling operation counters are separate from latency and have no independence-based intervals. Export timestamps are removed and SVG IDs use a fixed salt so repeated offline runs produce identical bytes in the same installed plotting environment. Every output is immutable. The figure manifest binds the analysis manifest and every exported file.

No production file, generator, benchmark case, response or frozen plan is modified by this implementation. Regeneration commands, from the repository root, are `.venv/Scripts/python.exe scripts/analyze_phase11.py` followed by `.venv/Scripts/python.exe scripts/plot_phase11.py`. Focused hand-derived tests are `tests/test_analysis_v11.py` with a temporary directory under `work/p11-analysis`.
